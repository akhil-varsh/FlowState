What it does

A memory for your working state — not a spy in your editor.

Everything FlowState knows comes from tools that already know it: the editor's own document model, your git repo, your shell. No OCR. No pixels. No accounts.

Ground-truth capture

Open files, cursor, selection, recent edits, terminal commands with exit codes, diagnostics, and git branch — read straight from the VS Code API and git, never from your screen.

“Where you left off” briefings

A local model (deepseek-r1) turns a snapshot into a plain-English recap of what you were doing and the obvious next step — generated on your CPU, in seconds.

One-click rehydrate

Reopen every file from the session at the exact line you left — right inside VS Code. The room is exactly as you left it before the interruption.

Semantic history search

“That afternoon I fought the websocket reconnect” → the exact session. On-device embeddings (all-MiniLM via ONNX) power search only; restore stays a pure SQL lookup.

Desktop widget & kill-switch

A small always-on card sits bottom-right showing your last capture — with one toggle to pause recording whenever you want privacy, and resume when you don't.

Encrypted & ephemeral

Optional at-rest encryption (Fernet + PBKDF2) on the snapshot payload, and a TTL sweeper that purges old sessions from both stores in lockstep. Your history doesn't pile up forever.

How it works

Three tiers in. One SQL lookup out.

A local FastAPI daemon assembles context from three ground-truth tiers, indexes it, and serves your last session back the instant you ask for it.

The moment that matters

The interruption is the enemy. Rehydration is the cure.

  • Read the briefing. A two-line recap of what you were doing and what's next — no re-reading your own diff to remember.
  • Hit rehydrate. Every file reopens at its cursor line, in order — from the dashboard, the widget, or the command palette.
  • Keep typing. The failing test, the open branch, the half-written function — all exactly where you left them.

Get FlowState

Installed and capturing in three steps.

One signed Windows installer bundles the daemon (no Python needed), the desktop widget, and the VS Code extension — then registers everything to start with your session.

1

Run the installer

Download and launch FlowState-Setup.exe. It's a per-user install — no admin rights required.

FlowState-Setup.exe
2

Pull the local model

Install Ollama, then pull the default 1.5B model once. After this, FlowState never needs the network again.

ollama pull deepseek-r1:1.5b
3

Work as usual

Open your project in VS Code. FlowState captures in the background. When you come back, press the shortcut and rehydrate.

Privacy by construction

These aren't settings. They're guarantees.

FlowState's privacy isn't a toggle you trust — it's the way the system is built. Here's what that means, line by line.

Loopback only

Every server binds 127.0.0.1 — never 0.0.0.0. Nothing on your network, let alone the internet, can reach it.

No pixels, ever

Capture comes from the editor's API, git, and the shell — never OCR, screenshots, or reading other apps' contents. Ambient reads only window title, process name, and clipboard.

Fully offline

After one model pull, FlowState makes zero outbound calls and sends zero telemetry. Turn off Wi-Fi and it works exactly the same.

Your data, your disk

Everything lives in %LOCALAPPDATA%\FlowState, optionally encrypted, auto-expiring on a TTL. Uninstalling leaves your data untouched — or you delete the folder.

Answers

Questions, answered plainly.

Is FlowState only for VS Code?
The deepest, richest capture — files, cursor, terminal, diagnostics, one-click rehydrate — comes through the VS Code extension, because that's where ground-truth editor state lives. A lighter ambient tier notes your active window title, process name, and clipboard across the whole desktop, so a snapshot can record that you'd stepped over to a browser or terminal. It does not read the contents of other apps or which specific web pages you viewed — that would require screen scraping, which FlowState never does by design.
Does it capture my browser and which sites I visited?
Only the window title of whatever app is in the foreground (which may include a tab's title) plus the process name — never the page contents, URL history, or a list of your tabs. Reading your browsing would require the kind of screen or history scraping FlowState refuses to do. If you want richer browser context, that would be a separate, explicitly opt-in feature.
“Could not reach the daemon on 127.0.0.1” — what do I do?
The extension talks to the local daemon on port 8420. If it's unreachable: confirm the daemon is running (curl 127.0.0.1:8420/health), that the "FlowState Daemon" logon task started, and that Ollama is running. The installer registers the daemon to autostart at logon; after a fresh install, sign out and back in — or start it from the Start menu — and retry.
Why deepseek-r1:1.5b and can I change it?
It's the default because it fits a 16 GB, CPU-only laptop while still writing a useful briefing (warm restores land in ~20s). It's the only officially supported model. Advanced users can technically point FLOWSTATE_MODEL or config.toml at another Ollama model, but the docs and installer are tuned for deepseek.
How much does it slow my machine down?
The daemon is event-driven, not polling — measured idle at about 0.02% CPU and ~156 MB RSS, well under the <5% budget. Inference only runs when you actually restore or when a briefing is generated, never in the background on a timer.
Where do my snapshots live, and can I wipe them?
In %LOCALAPPDATA%\FlowState — the SQLite database, the Chroma index, your config, and the recording state. They auto-expire on the TTL, you can force a purge via the API, and uninstalling deliberately leaves the folder so nothing is lost by accident. Delete the folder to wipe everything.
