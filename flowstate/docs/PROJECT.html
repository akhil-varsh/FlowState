00 — Overview

The cost of an interruption

Every interruption costs roughly 23 minutes of rebuilding mental context — which file, which line, which branch, what the terminal just said, what you were about to try. FlowState removes that reload. It watches the tools that already hold the truth of your session, snapshots them the moment you're pulled away, and hands the context back as a short briefing when you return.

Three surfaces cooperate, and all of them run on your machine:

daemon · FastAPI

The orchestrator

An async daemon on 127.0.0.1:8420 that assembles snapshots, runs on-demand inference, stores history, and drives rehydration.

extension · VS Code

Ground truth

Captures editor, terminal, and diagnostic state straight from the Extension API — no OCR, no screen scraping.

dashboard · Next.js

The window

An animated landing page and a working dashboard that shows the briefing, the timeline, and semantic search.

01 — Non-negotiable constraints

The constraints are the design

These aren't preferences — they govern every decision in the codebase. The architecture is what it is because of them.

Fully offline

After one initial model download, zero outbound calls and zero telemetry. The system runs with the network physically disconnected.

Localhost only

Every server binds 127.0.0.1 — never 0.0.0.0. Nothing is ever exposed to a network interface.

Ground-truth capture

State comes from the editor API, git, and the shell. Never OCR, never screenshots, never reading other apps' window contents.

No vectors on restore

The restore path is a single indexed SQL lookup. Vector search exists only for the separate "search my history" feature.

Event-driven & cheap

Under 5% CPU at idle. No polling loops; inference runs on-demand only, never in the background.

Ephemeral by default

Snapshots auto-expire on a configurable TTL, purged from both stores in lockstep. Optional at-rest encryption.

02 — System architecture

Five layers, one machine

The daemon is the hub. Capture sources feed it structured tiers, it persists to two purpose-built stores, and inference is pulled from a local model only when the user actually returns. The dashboard and extension speak to it over REST and two WebSocket channels.

Nothing crosses a network boundary. The only three processes are the Python daemon, the Node dashboard server, and VS Code — plus the local Ollama server for the model. Each binds to the loopback interface and nothing else.

03 — The defining decision

Two paths that never cross

The single most important architectural rule: restore and search are different problems with different data structures. Restoring is "give me the latest state of this workspace" — a keyed lookup that must be instant and exact. Searching is "which past session was about auth?" — a fuzzy, meaning-based query. Conflating them would make restore slow and non-deterministic.

Why it matters

Because the two paths are physically separate — different modules, different stores — restore stays a sub-millisecond keyed read even as the vector index grows to thousands of sessions. Search quality can improve independently without ever putting a probabilistic step on the critical "get me back to work" path.

04 — Capture pipeline

Three tiers, merged by the assembler

A snapshot is deliberately small (2–8 KB of structured fields, never file dumps). It is built from three tiers of increasing distance from the editor. The extension owns Tier 1 — the ground truth — and the daemon fills Tiers 2 and 3, never overwriting what the extension already provided.

tier 1 · VS Code API

Editor

1-based cursor, open + dirty files, rolling edit ranges, shell-integration command output, and current diagnostics.

tier 2 · pygit2

Git

Branch, dirty files, a capped diff summary, and recent commits — read by the daemon, with a git-CLI fallback.

tier 3 · pywin32

Ambient

Only the active window's title + process name and the clipboard text. Never other apps' contents.

Triggers that fire a capture — focus_loss (debounced so a quick alt-tab is ignored), idle, and manual — are detected in the extension, where the reliable focus and activity events live. Their thresholds come from the daemon's /config, so there is a single authoritative place to tune policy.

07 — Rehydration loop

From briefing back to cursor

Clicking Rehydrate on the dashboard closes the loop: the daemon relays the target files to the extension over a persistent WebSocket, and the extension reopens each at its exact line. The daemon reports honestly whether an extension was actually listening.

08 — Local inference

On-demand, structured, always answers

Inference runs against the local Ollama server, and only when GET /restore is called — never in the background. Output is forced to valid JSON via Ollama's schema-constrained decoding, so freeform text is never parsed and a reasoning model's <think> block can't leak.

  • Structured output. The Summary JSON schema is passed as the grammar; the model can only emit valid fields.
  • Deterministic backfill. files_to_reopen is filled from the snapshot itself, so rehydration targets never depend on the model echoing paths.
  • Graceful fallback. If Ollama is down or the model is missing, a deterministic briefing is built straight from the snapshot — specific because the snapshot already is, and it works with the network off.
  • Kept warm, not busy. keep_alive holds the model resident during work hours to cut latency; it is never invoked without a user action.
The model

deepseek-r1:1.5b (~1.1 GB) is the default and only supported model — small enough for the tight-RAM, CPU-only target, with a warm restore latency of ~20 s. It ships as the default, so a fresh install needs no model configuration.

A real engineering call

The spec named sentence-transformers for embeddings, which pulls in PyTorch — and PyTorch has no wheels for Python 3.14, the interpreter on this machine. ChromaDB's built-in default embedder is all-MiniLM-L6-v2 served through ONNX Runtime: same model, no torch, lighter on a no-GPU laptop. Same result, better fit.

11 — Privacy & security

Private by construction

Privacy here isn't a policy page — it's a property of the architecture. There is no server to send data to.

Zero egress

After the one-time model pull, no outbound calls and no telemetry — including ChromaDB's, which is explicitly disabled. Verified with Wi-Fi off.

Ephemerality

A sleep-driven sweeper deletes snapshots past their TTL from SQLite and the vector index in lockstep, and it's exposed on-demand too.

At-rest encryption

Optional. Set a passphrase and the snapshot payload is Fernet-encrypted (PBKDF2-derived key); index columns stay plaintext so restore stays a plain lookup.

Minimal ambient reach

The ambient collector reads only a window title, a process name, and the clipboard — never another app's contents, never a screenshot.

13 — Run it

From clone to offline demo

# one-time, online — the only network operations
./scripts/setup.ps1                         # venv + deps
./scripts/pull-model.ps1 deepseek-r1:1.5b   # the local LLM
./scripts/pull-embed.ps1                    # the ONNX embedder

# then — turn Wi-Fi OFF and run fully local
ollama serve                                # local model server
./scripts/run-daemon.ps1                    # 127.0.0.1:8420
./scripts/run-dashboard.ps1                 # 127.0.0.1:3000
# F5 the extension/ folder in VS Code → capture, restore, rehydrate

In VS Code, edit a file and press Ctrl+Alt+S to capture. On the dashboard, Restore produces a real briefing, Rehydrate reopens the file at its cursor, and Search finds the session — all with the network physically disconnected.
